## סיבוב המסך והתאמת המצלמה

### א. למה העצמים נראים גדולים יותר במצב אנכי?

במצלמה אורתוגרפית, התכונה **Size** (`orthographicSize`) קובעת את **חצי מגובה העולם** שהמצלמה מציגה, ביחידות עולם. הערך הזה קבוע ולא תלוי בצורת המסך.

לכן כל יחידת עולם תופסת על המסך `גובה המסך בפיקסלים / (2 × Size)` פיקסלים.

כשמסובבים את הטלפון ממצב אופקי למצב אנכי, **גובה המסך בפיקסלים גדל** (הצלע הארוכה הופכת לגובה), אבל ה־Size נשאר אותו דבר. אותו גובה של עולם נפרס על יותר פיקסלים, ולכן **כל העצמים נראים גדולים יותר**.

**דוגמה:** בטלפון 1920×1080 עם Size = 5:
- במצב אופקי, גובה המסך 1080 פיקסלים: 1080 / 10 = **108 פיקסלים ליחידה**.
- במצב אנכי, גובה המסך 1920 פיקסלים: 1920 / 10 = **192 פיקסלים ליחידה**, והעצמים גדולים פי 1.78.

### ב. הפתרון: הרכיב `CameraAspectAdjuster`

הרכיב משנה רק את ה־`orthographicSize` של המצלמה, בלי לשנות את גודל השחקן או של עצמים אחרים.

הרעיון: הצלע **הקצרה** של המסך נשארת אותו מספר פיקסלים בשני המצבים. לכן מחשבים את ה־Size כך שמספר הפיקסלים ליחידת עולם יישאר קבוע:

`orthographicSize = landscapeSize × גובה המסך / הצלע הקצרה`

- **במצב אופקי:** הגובה הוא הצלע הקצרה, ולכן Size = `landscapeSize` (5).
- **במצב אנכי:** Size גדל ביחס לגובה המסך, כך שכל יחידת עולם נשארת באותו גודל על המסך.

בדוגמה של 1920×1080: במצב אנכי Size = 5 × 1920 / 1080 ≈ 8.9, ו־1920 / 17.8 = **108 פיקסלים ליחידה**, בדיוק כמו במצב אופקי.

**התוצאה:** השחקן והקירות נראים באותו גודל בשני המצבים. במצב אנכי רואים יותר מהעולם למעלה ולמטה, ופחות לרוחב.

הרכיב מחשב מחדש רק כשגודל המסך משתנה, ולא בכל פריים. הערך `landscapeSize` מוגדר כ־`[SerializeField]`, ואפשר לשנות אותו ב־Inspector.

- `Assets/` – סצנות, אובייקטים וסקריפטים של המשחק.

- `ProjectSettings/` – הגדרות הפרויקט.
- `.github/workflows/` – הגדרת בדיקה אוטומטית של קוד C#.
